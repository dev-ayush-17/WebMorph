# Undying Scraper — Journey from v0.1 to v1.0

This changelog summarizes the full engineering journey of building **Undying Scraper** for the Bright Data Scraper Studio × WeMakeDevs hackathon.

---

## 📅 Version History & Milestones

### 🕷 Version 0.1 — The Orchestration Skeleton
- **Goal**: Establish the data contract and basic pipeline flow against a mock data source.
- **Accomplishments**: 
  - Designed the core data contract (name, price, currency, stock, url, scraped_at).
  - Built the `run-pipeline.js` orchestrator, `heal-check.js` validator, and `mock-source.js` generator.
  - Implemented graceful dry-run fallback if Supabase is unconfigured.
  - Styled the Next.js dashboard using the Space Grotesk/Mono **Terminal Amber** theme.

### 🔌 Version 0.2 — Live Integration & Mode Switching
- **Goal**: Integrate the real Bright Data CLI and enable zero-code mode switching.
- **Accomplishments**:
  - Wrote a robust Node.js child_process wrapper (`src/brightdata/client.js`) around the `bdata` CLI.
  - Built `collector-registry.js` as the single source of truth to dispatch runs to `LIVE` (CLI) or `MOCK` based on `.env` keys.
  - Wired real `bdata scraper heal` triggers for live extraction failures.
  - Wrote 20 unit tests for registry and client wrapper (using injected child_process mocks).

### 🛡 Version 0.3 — Pipeline Hardening & Dashboard Polish
- **Goal**: Add database persistence for runs, implement price delta diffing, and expand metadata.
- **Accomplishments**:
  - Implemented `src/diff.js` to compare scraped items against prior Supabase snapshots, flagging price changes and stock flips.
  - Created a `runs` table to log start/end timestamps, statuses, and full structured summary JSON payloads.
  - Added retry-with-linear-backoff wrapper (`src/retry.js`) for resilient heal attempts (max 2 tries).
  - Polished the dashboard with ▲/▼ price delta badges, stock status change notifications, and a Run History log.
  - Created 21 integration tests (`tests/pipeline-integration.test.js`) verifying retry, heal-check, and diffing modules.

### ⚡ Version 0.4 — Target Site Confirmed & Normalization
- **Goal**: Confirm target site (Raajkart.com Physics Books) and handle real-world parsing quirks.
- **Accomplishments**:
  - Created and registered the live scraper template `c_mt4qg4m3ri0w861pe` for Raajkart.com.
  - Built a comprehensive normalization layer (`src/brightdata/normalize.js`) to parse real-world quirks (e.g. converting "Rs 299.00" strings to numbers, translating rupee symbols, normalizing relative URLs, and mapping in-stock text).
  - Wrote 35 unit tests (`tests/normalize.test.js`) covering all parsing edge cases.
  - Swapped the seed mock catalog to generate realistic Raajkart Physics book data (INR, ₹150–₹1200 ranges) to preserve high-fidelity testing.

### 🏆 Version 1.0 — Final Submission Polish
- **Goal**: Clean up the codebase, verify production build stability, and prepare documentation.
- **Accomplishments**:
  - Conducted a full secrets audit across git history (confirmed clean).
  - Formatted all source code with Prettier for clean, consistent styling.
  - Verified a zero-error Next.js production build (`npm run build` compiled cleanly in 24s).
  - Prepared submission documentation: Vercel deployment steps, GitHub Secrets guidelines, CodeRabbit integration checklist, and a 2.5-minute video demo script.
